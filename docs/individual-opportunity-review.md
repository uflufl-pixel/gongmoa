## 수집기 점검 결과

현재 lib/bizinfo-detail.ts는 plain() 처리로 링크 href를 버린다. 신청 URL이 본문에 글자로 기재되지 않으면 신청방법 설명만 남을 수 있다. 또한 상세 병합에서 institution을 수행기관으로 덮어쓰지만 목록 group은 소관기관 기준으로 유지되어 역할이 혼재한다.

후속 구현 조건:

1. 공식 '사업신청 사이트' 항목에서만 신청 URL을 추출하고 출처 링크와 분리한다.
2. HTTP(S), 자격증명 없는 URL만 허용하고 임의 링크를 서버에서 호출하지 않는다.
3. 방문·우편·이메일 접수는 온라인 접수로 바꾸지 않는다. 복수 접수처도 보존한다.
4. 기존 상세 payload의 필드 누락을 허용해 이전 데이터와 호환한다.
5. 발행·소관기관과 수행기관을 분리하고 명칭으로 기관 유형을 추측하지 않는다.
6. 감사의 변경 감지에 실제 신청조건·접수처를 포함한다. 상세 파싱 성공만으로 verified 승격하지 않는다.

기존 기업마당 상세 단위 테스트 4건 통과. 이 테스트는 위 두 개선점의 구현 완료를 뜻하지 않는다.

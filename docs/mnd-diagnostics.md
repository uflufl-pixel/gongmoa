# 국방부 운영 요청 진단

2026-09-03: 로컬 공식 RSS 요청은 HTTP 200, DNS 0.002초, TCP 0.079초, TLS 0.121초, 첫 바이트 0.298초, 완료 0.392초였다. 운영 수집은 국방부만 약 20초 후 TimeoutError이며 해당 수집 API 자체는 HTTP 200으로 정상 완료했다. 기존 기록만으로 응답 헤더 대기와 본문 수신 실패를 구분할 수 없다.

국방부 한정 `fetchTextWithDiagnostics`를 적용한다. 기존 요청 예외 1회 재시도와 HTTP 408/429/5xx 추가 1회 재요청, 본문 실패 재시도 없음 정책을 보존한다. 요청별 10초 제한도 유지한다. 오류 메시지에 최대 3회 시도의 헤더 도착 시간(h), 해당 시도 시작부터 실패까지 시간(t), HTTP 상태, response/body/retry-http 단계를 기록한다. response는 fetch가 아직 응답 객체를 반환하지 않은 단계이며 DNS/TCP/TLS 중 어느 단계인지는 뜻하지 않는다.

시간은 단조 시계로 측정하고 메시지는 300자 이내의 숫자·고정 라벨만 저장한다. URL·헤더·쿠키·본문·원본 오류 내용은 기록하지 않는다. 본문 오류라면 실제 수신한 HTTP 코드를 보존하지만 outcome은 fetch_error이므로 HTTP 200만으로 수집 성공으로 판정하지 않는다. 정상 수집과 파서 결과는 기존 흐름을 유지한다. 데이터베이스 스키마와 수집 대상 URL을 변경하지 않는다.

서브에이전트가 재시도 순서, 최종 오류 분류, 민감정보 제외, 본문 실패 테스트를 읽기 전용으로 검토했으며 사이트 수정·검증·배포는 메인 에이전트가 수행한다.

운영 진단 결과: 두 시도 모두 response 단계, headersMs=null, 각각 10000ms timeout. 응답 객체를 받기 전에 실패했으며 DNS/TCP/TLS/원서버 대기 중 세부 원인은 아직 구분되지 않는다.

## 공식 대체 경로 비교

`POST /api/mnd-probe`는 공지 RSS 50행/10행, 공식 공지 HTML, 공식 안내에 실린 공고·고시 RSS의 고정된 네 주소만 검사한다. 쿼리 인자는 거부하며 본문 입력을 외부 요청에 사용하지 않는다. 전체 공유 10초, 각 주소 1회, redirect 미추적, 응답별 512KB 상한이다. 숫자·상태만 반환하며 데이터베이스/공고/수집 성공 상태를 변경하지 않는다. detailPathMarkers는 본문 경로 문자열 개수일 뿐 검증된 공식 링크나 공모 개수가 아니다.

공식 경로 근거: 국방부 RSS 이용안내 `https://www.mnd.go.kr/mnd/343/subview.do`. 공고·고시 게시판 26390은 공지 11066과 별개의 목록이다. 작업 환경에서 네 경로 모두 HTTP 200이고 공지는 50/10행, HTML 경로 문자열 15개, 공고·고시 RSS는 1항목이었다. 응답 성공만으로 대체 수집원으로 인정하지 않으며 실제 내용과 운영 접근을 별도 검증한다.

공고·고시 RSS의 단일 항목을 추가 확인한 결과 `This board unsupportable RSS function.` / `NOT SUPPORT RSS` 안내였다. 실제 공고 1건이 아니며, 공식 안내에 주소가 있어도 현재 수집 가능한 RSS가 아니다. 이 경로는 자동 수집에 연결하지 않는다. 검사는 운영과 작업 환경 차이를 확인하는 용도로만 남긴다.
